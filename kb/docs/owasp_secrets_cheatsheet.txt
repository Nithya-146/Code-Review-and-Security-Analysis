OWASP COMPREHENSIVE CHEAT SHEET: SECRETS AND SENSITIVE CREDENTIAL MANAGEMENT
================================================================================
Category: OWASP Top 10 A07:2025 - Identification and Authentication Failures
Common Weakness Enumeration: CWE-798 (Use of Hard-coded Credentials)
Severity: High to Critical (CVSS 7.5 - 9.8)

1. VULNERABILITY MECHANISM AND ATTACK VECTORS
Hardcoding secrets involves placing unencrypted API tokens, database passwords, OAuth client secrets, private RSA/ECDSA keys, or encryption passphrases directly into source code, build scripts, Dockerfiles, or configuration files.

Common Exposure Scenarios:
- Public GitHub/GitLab repository exposures due to accidental commits.
- Git commit history retention: Deleting a secret in a subsequent commit leaves it permanently visible in previous Git commits and blobs.
- Client-side decompilation: Compiling code into mobile APKs, desktop executables, or web frontends exposes embedded strings to reverse engineering.
- Intermediate build artifact exposure: Packaging plaintext credentials in container image layers (`docker history`).

2. ENVIRONMENT-BASED SECRET INJECTION
Never check credentials into version control. Secrets must be supplied externally via environment variables managed by the host execution environment, container orchestration platform, or a `.env` file that is strictly ignored by version control.

A. Python Configuration Patterns:

1) Vulnerable Pattern (Hardcoded API keys / passwords):
   DATABASE_URL = "postgresql://dbuser:supersecretpass123@prod-db.internal:5432/app"
   STRIPE_API_KEY = "placeholder_stripe_api_key"
   JWT_SIGNING_KEY = "super_secret_jwt_hmac_secret"

2) Secure Pattern using `python-dotenv` and `os.environ`:
   import os
   from dotenv import load_dotenv

   # Load variables from local .env for development
   load_dotenv()

   DATABASE_URL = os.getenv("DATABASE_URL")
   if not DATABASE_URL:
       raise RuntimeError("CRITICAL ERROR: DATABASE_URL environment variable is unset.")

   STRIPE_API_KEY = os.getenv("STRIPE_API_KEY")
   if not STRIPE_API_KEY:
       raise RuntimeError("CRITICAL ERROR: STRIPE_API_KEY environment variable is unset.")

B. Java Enterprise Configuration Patterns:

1) Vulnerable Pattern:
   public class DatabaseConfig {
       public static final String DB_USER = "admin";
       public static final String DB_PASS = "ProductionSecureP@ss2026!";
   }

2) Secure Pattern (System.getenv or Spring Boot Property Binding):
   public class DatabaseConfig {
       public static String getDatabasePassword() {
           String pass = System.getenv("DB_PASSWORD");
           if (pass == null || pass.trim().isEmpty()) {
               throw new IllegalStateException("CRITICAL ERROR: DB_PASSWORD environment variable is missing.");
           }
           return pass;
       }
   }

   Spring Boot `application.properties` (delegating to environment variables):
   spring.datasource.url=\${DB_URL}
   spring.datasource.username=\${DB_USER}
   spring.datasource.password=\${DB_PASSWORD}

3. CENTRALIZED SECRET MANAGERS & DYNAMIC CREDENTIALS
For scalable enterprise deployments, hardcoded static credentials should be replaced with centralized key management systems (KMS) and dynamic, short-lived secrets.

Recommended Secret Storage Systems:
- HashiCorp Vault: Delivers dynamic, leasing credentials, automated secret rotation, and granular access audits.
- AWS Secrets Manager / Azure Key Vault / Google Secret Manager: Native cloud key stores providing zero-trust identity integration (e.g., AWS IAM roles for service accounts, Azure Managed Identities).
- Doppler / CyberArk: Centralized credential orchestration for developer environments and CI/CD pipelines.

4. AUTOMATED PRE-COMMIT AND CI/CD SECRET SCANNING
Implement automated guards to detect and reject credentials before they reach remote repositories.

Recommended Tools and Integrations:
- detect-secrets / git-secrets: Runs as local pre-commit Git hooks to analyze staged code diffs against entropy thresholds and regular expressions.
- Gitleaks / TruffleHog: Scans Git trees, commit histories, branch histories, and container images for leaked high-entropy secrets and specific cloud token patterns.
- GitHub Secret Scanning / Push Protection: Blocks git pushes directly on GitHub if recognized token patterns (e.g., AWS keys, Slack webhooks, OpenAI API keys) are detected.

5. ACCIDENTAL COMMIT INCIDENT RESPONSE PLAYBOOK
If a credential is ever committed to version control:
1. Revoke Immediately: Immediately revoke, delete, or rotate the compromised token or password at the service provider.
2. Invalidation Over Deletion: Simply deleting the commit or rewriting Git history with `git filter-repo` does NOT eliminate the risk; assume the secret was captured by scrapers within seconds.
3. Audit Logs: Inspect audit access logs for the compromised credential to verify if unauthorized access or anomalous activity occurred during the exposure window.================================================================================
